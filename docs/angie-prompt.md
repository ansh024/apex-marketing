## Design system

Set these up first as Elementor **global variables**, then reference them everywhere
instead of typing hex codes.

**Prefix every global class name with `apex-`.** `container` is a reserved name
Elementor rejects, and class import merges by label, so an unprefixed `section` or
`btn` will silently merge with whatever the site already has.

### Type

- One family throughout: **Arimo**, or the site's existing sans. No second family.
- Three voices only:
  - **Voice** for headings. Tight tracking, about -0.03em, weight 600.
  - **Data** for small uppercase labels, wide tracking, about 0.14em. **Labels and short facts only, never a sentence.** Setting a sentence in tracked uppercase is the single thing that makes this design look machine-generated.
  - **Body** in normal case, line-height about 1.45, colour `ink-muted`.
- Headline sizes are fluid and step up at the laptop breakpoint.

### Layout rules

- Content sits in a centred container, max-width `container-max`, with side padding
  that steps up at tablet and laptop.
- Sections are separated by generous vertical padding, roughly 96px rising to 160px
  on laptop.
- Hairline rules, 1px in `rule` or `rule-strong`, do most of the separating.
  **Prefer a rule over a box.** Very little on this page is a card.
- Corners are mostly square. Only buttons are pill-shaped, and only the service cards
  have a small radius.
- **Do not repeat a layout family.** The nine sections use nine different
  arrangements on purpose. A new section needs a new arrangement, not a second copy
  of the service card grid.

### Copy rules

- **No em-dashes or en-dashes anywhere.** Use a full stop or a comma.
- A line either says something only true in this city, or says the sitewide sentence
  unchanged. Half-localised phrasing like "built around Austin's highest-value
  neighborhoods" is what reads as machine-written.
- Do not invent local proof: no client names, city-specific statistics, or
  "we know this market" claims.

## Three things Angie cannot do, that need a manual step

1. **The booking form.** Leave an empty container in the Book section, then add an
   Elementor **HTML widget** with this iframe:

   ```html
   <iframe src="https://api.leadconnectorhq.com/widget/form/PV33s1v3pTF8y2bzSIIs"
           title="Book a free strategy call with Apex Marketing"
           style="width:100%;min-height:640px;border:0;display:block" loading="lazy"></iframe>
   ```

2. **A collapsing FAQ.** The atomic element set has no accordion. Either leave the six
   rows open, or use Elementor Pro's **Accordion** widget. Same copy either way.

3. **The faint grid texture** behind each section, about 5% opacity. It is a repeating
   grid, and Elementor's gradient overlay has no background-size, so it cannot be made
   from a gradient. To add it: upload a 220x220 PNG of one grid cell, a 1px ink line on
   the top and left edges and transparent elsewhere, then set it as a background image
   overlay with repeat, sized 220x220. Purely decorative.

## When it is built

The city-specific strings become dynamic tags against the `apex_location` post type,
so one template serves every city. The fields are `apex_city`, `apex_state`,
`apex_state_abbr`, `apex_timezone`, `apex_hero_h1` and `apex_hero_lede`, plus the
`apex_service_area` taxonomy for coverage. See `docs/elementor-authoring.md` section 7.

One number changes when you do. The hero plate's "Areas served" reads **8** here,
meaning the nearby towns, while `apex_location_areas_count()` returns **9**, meaning
every town in the coverage taxonomy including the city itself. Both are right for
their own definition, so decide which one the plate should show before binding it,
rather than being surprised when the number moves.
